# Миграция и совместимость

Это руководство описывает актуальный компактный API GoyGram. Предпочитайте публичный объект `GoyGram` и документированные объекты событий приватным полям транспортов.

## Python и установка

GoyGram требует Python 3.11 или новее. Установка и обновление:

```bash
python -m pip install -U goygram
```

При разработке из чекаута ставьте проект в то окружение, из которого запускаете приложение, чтобы Python импортировал тот же исходник, который вы редактируете.

## Динамические методы вместо сгенерированных обёрток

Вызовы Bot API динамические. Переводите имена методов Telegram в snake_case:

```python
await app.send_message(chat_id=123, text="Привет")
await app.get_me()
```

Вызовы MTProto используют префикс `mt_`, разделитель пространства имён и snake_case дальше:

```python
await app.mt_users_get_full_user(id="me")
await app.mt_messages_get_history(peer="me", limit=10)
```

Не завязывайтесь на сгенерированные классы-обёртки под каждый метод. Правила конвертации — в [Вызовы Bot API](/docs/Bot-API-Calls) и [Вызовы MTProto](/docs/MTProto-Calls).

## Регистрация обработчиков

Используйте `on_msg()`, `on_cb()`, `on_poll()`, `on_member()` и `on_update()`. `on_cmd()` — короткая форма для обработчиков сообщений с командным фильтром.

```python
@app.on_cmd("start")
async def start(msg):
    await msg.reply("Привет")
```

Регистрация принимает и колбэк напрямую: `app.on_msg(handler, filt=...)`.

## Сессии MTProto

Аутентификация MTProto построена на сессиях. Храните session vault надёжно и стабильно между перезапусками; смена `session_name` означает другой целевой vault. Перед миграцией деплоя прочитайте [Сессии и аутентификация](/docs/Sessions-and-Authentication).

## Дисциплина совместимости

- Пиньте проверенную версию GoyGram для продакшена.
- Держите имена параметров Bot API в соответствии с текущей документацией Telegram.
- Считайте сырые вызовы MTProto-схемы чувствительными к версии и проверяйте их после обновлений схемы Telegram.
- Не трогайте `app.core`, reader'ы транспортов и внутренности диспетчера, если сознательно не поддерживаете интеграцию против приватного API.

Диагностику при обновлении смотрите в [Ошибки и диагностика](/docs/Errors-Logging-and-Troubleshooting).
